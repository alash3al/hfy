# Shared UI fixtures

These fixtures are the contract the embedded **JS UI** (`internal/httpapi/embed/ui.js`) and the
future **Dart SDK** must both satisfy: fold the same wire events into the same
turns/blocks, parse markdown the same way, and use the same strings and CSS
tokens. Everything generated here is produced **from the real code** — never
hand-edited:

- event sequences in `events/` are hand-authored (they are inputs),
- `expected/<name>.json`, `strings.json` and `markdown.json`'s trees are
  regenerated by `TestFixturesMatchJS -update-fixtures` (node, from the real
  `ui.js`),
- `tokens.json` is measured in a real browser against `/embed` (see below).

```sh
go test ./internal/httpapi -run TestFixturesMatchJS -count=1            # verify
go test ./internal/httpapi -run TestFixturesMatchJS -update-fixtures   # regenerate (needs node)
```

The Go test drives the real `window.hfyEmbed()` fold under node with the same
window/document stub level as `embed_test.go` (the fold never draws DOM). It
fails when ui.js and the committed projections drift apart — change ui.js, run
with `-update-fixtures`, and review the diff as the behavioral change it is.

## `events/<name>.json` — a wire sequence

The events **exactly as the server sends them** (docs/reference.md "Events",
payload shapes in `internal/types/payloads.go`):

```json
{
  "name":   "chat-streaming",            // == file name
  "path":   "live",                      // "live" (SSE, includes ephemeral text.delta) or "history" (a connect() page)
  "viewer": {"uuid": "u1", "type": "external", "ref": "u1"},   // the grant's actor, as /history returns it
  "hasOlder": true,                      // optional; client.hasOlder before any loadOlder
  "events": [ /* envelope v=1 below, oldest first */ ],
  "pages":  [ /* optional: extra history pages delivered through the REAL loadOlder, newest page first; each is {next, live_after, viewer, events} */ ]
}
```

Envelope (per event): `{id, type, parent, actor:{uuid,type,ref}, v, data,
created_at}`. Rules the test enforces on every file:

- `created_at` must be real RFC3339 (the projection carries ISO stamps; a
  fabricated stamp would make folds non-deterministic).
- `v` must be the current wire version (`1`) when present.
- A `turn` event's `id` **is** the turn id; children carry it as `parent`.

Delivery semantics: `path:"live"` folds through `fold(env, false)`;
`path:"history"` folds through `fold(env, true)` the way `connect()` replays a
history page; `pages:` are delivered through the component's real `loadOlder()`
(merging/deduping/overlap settlement included), as `HfyClient#loadHistory` does
while the loader collects.

## `expected/<name>.json` — the PROJECTION

One file per event sequence: the folded state after the last event (plus a
final `relayout(); syncDerived()`), as **one stable JSON view**. It records
every field the fold settles; it drops everything presentation-only.

```json
{
  "name": "…", "path": "live", "viewer": {…},       // echo of the fixture header
  "hasOlder": false,                                 // client.hasOlder after any loadOlder
  "showWelcome": true,                               // empty conversation => welcome card
  "pendingOwn": ["t1-c1"],                           // call ids of the viewer's open approvals, folded order
  "turns": [
    {
      "id": "turn-1", "agent": "main", "state": "running",
      "own": true,                                   // the starter's actor uuid == viewer.uuid
      "showTyping": true,                            // assistant-is-typing dots (a turn no block is busy in)
      "error": "…",                                  // only when turn.state {state:"failed"} carried one
      "blocks": [ /* oldest first */ ]
    }
  ]
}
```

Per block (fields appear only when meaningful; object keys are sorted at every
level so files diff cleanly):

Common:

| field | why |
|---|---|
| `id` | the folding event's id (streaming blocks get the synthetic `"<turnId>:stream"` / `"<turnId>:rstream"`) |
| `kind` | `text`, `reasoning` or `tool` — the only block kinds the fold builds |
| `iso` | ISO timestamp of the folding event (ordering/tag; formatted text is dropped) |

`text` additionally:

| field | why |
|---|---|
| `role` | `user` or `agent` (user vs agent speech) |
| `ref` | the actor's `ref` (group framing; `""` for anonymous) |
| `text` | the message text |
| `streaming` | true only while `text.delta`s are still pending their durable `message.text` |
| `attachments` | only when the wire carried any: `{name, mime, hasUrl, isImage}` — `name`/`mime` from the wire (the fold keeps only derived url/images), `hasUrl` = a served url existed, `isImage` mirrors the fold's `mapAtts` classification |

`reasoning` additionally: `text`, `streaming`.

`tool` (call + result + approval/ask all live on ONE block, keyed by `callId`):

| field | why |
|---|---|
| `callId`, `name` | the tool's identity; `""` name = a `tool_result` for a call the fold never saw |
| `status` | `running` / `done` / `error` / `interrupted` |
| `args` | the call's raw `arguments` (null when none) |
| `content` | the result text |
| `structured` | the wire's `tool_result.data.structured` (the fold keeps only a pretty-printed copy; the projection stores the wire JSON) |
| `isAsk` | `name === "hfy.ask_user"` |
| `questions` | normalized questions (`{id,text,type,required,placeholder,options}`) — the ask's argument set, possibly re-taken from `approval.requested.data.questions` |
| `answers` | the validated answers from `approval.decided.data.answers` (or the ask result fallback) |
| `askState` | only for question sets: `pending` / `other` / `answered` / `skipped` / `timeout` / `stopped` / `asking` |
| `decision` | `allowed` / `denied` from `approval.decided` |
| `declineReason` | the decision's `reason` (e.g. `timeout`) |
| `stopped` | the call settled with its turn's end (never awaiting a decision) |
| `showApproval` / `showDecided` | an open approval pause / it has settled |
| `showPendingOwn` / `showPendingOther` | who must act on the open pause (the viewer -> sheet; others -> read-only note); plain approvals only |
| `card` | the tool's `hfy/ui` block verbatim (`{v,type, cards…}`) |
| `cardButtonsLive` | send/host buttons enabled: the turn is the viewer's own, currently the newest, and the viewer owns nothing active |

Dropped on purpose (presentation-only or environment-dependent): row/bubble
class names, DOM, Alpine internals and derived labels that quote the string
tables (`statusText`, `waitingText`, `askStateText`, `actorLabel`, tick
labels…), formatted day/time text (ISO `iso` is kept), avatar/hue classes,
grouping and fold-in-view geometry, sheet wizard state (it follows
`pendingOwn`), token numbers/usage, and `model.usage`/`summary` events — note
the **UI fold ignores both** (no projection possible for them; a Dart SDK that
wants summary banners needs its own decision).

## `markdown.json`

`[{name, input, tree}]` — `input` hand-authored (one case per parser rule or
edge, including Arabic/RTL and emoji), `tree` generated by the real
`hfyMdParse`. The tree is the parser's output verbatim (`{t,c,v,href,level,lang…}`
nodes, keys sorted only for storage); a Dart SDK must build these trees — DOM
building (`hfyMdBuild`) is out of scope here.

## `strings.json`

`{"en": {…}, "ar": {…}}` — the exact tables generated from `HFY_STRINGS` in
`ui.js`. The test re-extracts them from the real file, so translation edits
fail the fixtures until regenerated.

## `tokens.json` — how it was measured

CSS tokens for light/dark and both densities plus accent-derivation vectors
(final computed values) for accents `#6366f1, #25d366, #e11d48, #0ea5e9,
#f59e0b`:

1. hfy was built from this repo (mock provider, fresh database `hfy_fixtures`
   in container `hfy-testdb`, 127.0.0.1:54330) and served `/embed` from
   `127.0.0.1:8630`.
2. `/embed` was opened as a **top-level page** in a fresh chrome-devtools tab;
   no grant was needed (the tokens land on `:root` as soon as the Alpine
   component mounts). The unrelated "hfy sim host" tab was left untouched.
3. theme/accent/density were switched with the documented `configure` bridge
   message (`window.hfy.receive({type:"configure", …})`).
4. Colors: a probe `<div>` was given `background-color: var(--X)` and read with
   `getComputedStyle` — the **final resolved color** (`color(srgb …)` /
   `rgb(...)`, `--hfy-on-accent` included, which is `hfyOnColor`'s AA fallback).
   Shadows: `box-shadow: var(--X)` probe. Sizes: raw
   `getComputedStyle(document.documentElement).getPropertyValue` (no `var()`
   inside them; identical across themes).

The full method is recorded inside `tokens.json` itself; its shape (sections
`method/themes/density/variables`, light+dark, 5 accents) is enforced by the
test, but its values can only be re-measured in a browser.
