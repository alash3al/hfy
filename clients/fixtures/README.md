# Shared UI fixtures

These fixtures are the contract the embedded **JS UI** (`internal/httpapi/embed/ui.js`) and the
future **Dart SDK** must both satisfy: fold the same wire events into the same
turns/blocks, parse markdown the same way, and use the same strings and CSS
tokens. Everything generated here is produced **from the real code** — never
hand-edited:

- event sequences in `events/` are hand-authored (they are inputs),
- `expected/<name>.json`, `strings.json` and `markdown.json`'s trees+hashes are
  regenerated by `TestFixturesMatchJS -update-fixtures` (node, from the real
  `ui.js`),
- `tokens.json` is measured in a real browser against `/embed` (see below).

```sh
go test ./internal/httpapi -run TestFixturesMatchJS -count=1            # verify
go test ./internal/httpapi -run TestFixturesMatchJS -update-fixtures   # regenerate (needs node)
```

The Go test drives the real `window.hfyEmbed()` fold under node with the same
window/document stub level as `embed_test.go` (the fold never draws DOM), plus a
page `location` (origin `https://embed.example`) because `hfySafeUrl` resolves
the server's relative `/v1/files/...` download urls against `location.href` —
exactly what `internal/httpapi/uploads.go` sends. It fails when ui.js and the
committed projections drift apart — change ui.js, run with `-update-fixtures`,
and review the diff as the behavioral change it is.

## `events/<name>.json` — a wire sequence

The events **exactly as the server sends them** (docs/reference.md "Events",
payload shapes in `internal/types/payloads.go`):

```json
{
  "name":   "chat-streaming",            // == file name
  "path":   "live",                      // "live" (SSE, includes ephemeral text.delta) or "history" (a connect() page)
  "viewer": {"uuid": "u1", "type": "external", "ref": "u1"},   // the grant's actor, as /history returns it
  "hasOlder": true,                      // optional; client.hasOlder before any loadOlder
  "config": {"tool_calls": "details"},   // optional; tool-call visibility mode (hidden|summary|details; default summary)
  "liveAfter": "ev-3",                   // optional; the connect page's live_after, required with any history content
  "minimize": true,                      // optional; the user drags the sheet down before the projection (real minimizeSheet())
  "minimizeAfter": "ev-3",               // optional; the user drags the sheet down MID-sequence (see below)
  "events": [ /* envelope v=1 below, oldest first */ ],
  "pages":  [ /* optional: extra history pages delivered through the REAL loadOlder, newest page first; each is {next, live_after, viewer, events} */ ]
}
```

Envelope (per event): `{id, type, parent, actor:{uuid,type,ref}, v, data,
created_at}`. Rules the test enforces on every file:

- `created_at` must be real RFC3339 (the projection carries ISO stamps; a
  fabricated stamp would make folds non-deterministic).
- `v` must be the current wire version (`1`) when present.
- A `turn` event's `id` **is** the turn id; children carry it as `parent`.
- Day separators came from the fold's **device time zone** in the browser; the
  harness fixes that choice by running node with `TZ=UTC` (set in
  `fixtures_test.go` before spawning it), and the Dart harness pins the same
  choice by injecting `HfyTz.utc()` into the fold (its production default is
  the device zone, `HfyTz.local()`), so scenarios that cross a calendar
  midnight (`grouping-gaps`) and `expected/*.json` in general are
  deterministic across machines. Keep that pin in any other harness.
- The sheet-manipulation hooks are the header's trailing `minimize: true` (it
  runs `minimizeSheet()` after ALL events and pages, right before the final
  projection) and `"minimizeAfter": "<event id>"` (it runs `minimizeSheet()`
  mid-sequence, right after delivering that event, then the sequence keeps
  flowing — that the sheet only CONTINUES minimized is exactly what a next
  approval can disprove). `minimizeAfter` validates in the header sanity of
  `fixtures_test.go` and loudly in the Dart harness: the id must name an event
  of the MAIN sequence (pages are not addressable) and at least one
  `approval.requested` must appear at or before it (a minimize without an open
  approval is a bad fixture); it applies once even against a re-delivered id.
  `events/sheet-reopen-on-new-call.json` uses it to pin the reopen rule
  (P-FOLD-049): approval A opens the sheet, `minimizeAfter` closes it, a
  SECOND approval B — a new pending call — re-opens it (`sheetOpen:true`,
  `showActionPill:false` in the expectation) in both the real JS fold and the
  Dart fold.

Delivery semantics: `path:"live"` folds through `fold(env, false)` — unless an
event carries `"history": true`. History-flagged events must form one **leading
run** and model a scenario that **connects over a history page and then
continues with live SSE events** (one scenario can therefore mix history and
live: see `events/history-then-live.json`); `path:"history"` folds everything
as `connect()`'s page. `text.delta`/`reasoning.delta` are ephemeral and can
never be history. After the leading history run the harness pins
`liveAfter` into the projection's `lastEventId`, as `HfyClient#connect` does,
and every live delivery moves it from there. `pages:` are delivered through the
component's real `loadOlder()` — `HfyClient#loadOlder` fetches **one page per
call**, so the harness keeps calling `loadOlder()` while `hasOlder` holds (a
scenario needing two pages therefore exercises two calls) — with the
component's merging/deduping/overlap settlement included.

### Duplicate delivery (the client.js rule the Dart client must copy)

Every delivery — live, history, and loadOlder pages — goes through a client-like
`fire()` that mirrors `HfyClient`'s private `#fire` (client.js:165-173):

1. an envelope with `id != null` is delivered **at most once**: a per-client
   seen-set tracks every id, and a re-delivered envelope is dropped entirely
   (before it can fire, move the cursor, or fold);
2. only a **live** delivery (not history) updates `lastEventId`; since a
   re-delivered id is dropped before anything else, an envelope updates the
   cursor exactly once, on its first (necessarily live) delivery.
   `liveAfter`/history deliveries never touch the cursor.

So a reconnect that replays a `text.delta` under the same envelope id cannot
double-append text, and replayed durable events cannot duplicate blocks — the
fixture `events/dedupe-duplicate.json` pins both on purpose (its turn ends
mid-stream: without the dedupe the deltas would read `HeHel…` instead of
`Hello…`). The fold-level merge in `loadOlder()` (dedupe by block id) remains a
second safety net behind this one.

## `expected/<name>.json` — the PROJECTION

One file per event sequence: the folded state after the **last** event (plus a
final `relayout(); syncDerived()`, and `minimizeSheet()` for `minimize`
scenarios), as **one stable JSON view**. It records every field the fold
settles; it drops everything presentation-only.

Mid-stream states are pinned by fixtures that **end mid-stream on purpose**
(text deltas still streaming, reasoning deltas, two active turns, an ask that
has never been surfaced…) — the final state of such a scenario IS its
mid-stream state, and a mutation that changes any of it makes the comparison
against `expected/*.json` fail.

```json
{
  "name": "…", "path": "live", "viewer": {…},       // echo of the fixture header
  "config": {"tool_calls": "summary"},              // the effective visibility mode the fold ran with
  "lastEventId": "ev-3",                            // http stream cursor (live deliveries move it; history pins liveAfter)
  "hasOlder": false,                                 // client.hasOlder after any loadOlder
  "showWelcome": true,                               // empty conversation => welcome card
  "pendingOwn": ["t1-c1"],                           // call ids of the viewer's open approvals, folded order
  "sheetOpen": true,                                 // the approval sheet state (auto-open / minimized)
  "showActionPill": false,                           // "action needed" pill (sheet minimized while calls pend)
  "turns": [
    {
      "id": "turn-1", "agent": "main", "state": "running",
      "own": true,                                   // the starter's actor uuid == viewer.uuid
      "showTyping": true,                            // assistant-is-typing dots (a turn no block is busy in)
      "error": "…",                                  // only when turn.state {state:"failed"} carried one
      "blocks": [ /* oldest first */ ]
    }
  ]
}
```

Per block (fields appear only when meaningful; object keys are sorted at every
level so files diff cleanly):

Common:

| field | why |
|---|---|
| `id` | the folding event's id (streaming blocks get the synthetic `"<turnId>:stream"` / `"<turnId>:rstream"`) |
| `kind` | `text`, `reasoning` or `tool` — the only block kinds the fold builds |
| `iso` | ISO timestamp of the folding event (ordering/tag; formatted text is dropped) |
| `showDay` / `showHead` | grouping, computed in `relayout()`: `showDay` marks the day's first visible block (calendar day changes); `showHead` a new group (day change, actor change, or a text block more than 5 minutes after the previous one) — both are measured against the previous **visible** block of any kind, hidden tool blocks show no separator and reset nothing; the day/time zone they derive from is pinned to UTC by the harness (see the header rules above), the label text itself is presentation-only and dropped |

`text` additionally:

| field | why |
|---|---|
| `role` | `user` or `agent` (user vs agent speech) |
| `ref` | the actor's `ref` (group framing; `""` for anonymous) |
| `text` | the message text |
| `streaming` | true only while `text.delta`s are still pending their durable `message.text` |
| `attachments` | exactly what the fold computes for the block (`setAtts` → `mapAtts`), as `{images: […], files: […]}`, present only when a message carried any: each entry is the real `{url, label, isImage, isLink, isPlain}` — `url` is the **absolute url after `hfySafeUrl`** (relative `/v1/files/…` resolved against the page origin, `javascript:` and other unsafe schemes dropped to `""`), `label` `name ‖ mime ‖ t('file')`, `isImage` a safe url + `image/*` mime (goes to `images`), `isLink` a safe non-image link (goes to `files`), `isPlain` anything without a safe url; the fold additionally assigns each entry an internal `k` (a stable id like `(file‖url‖mime):i` it only ever uses as Alpine's `x-for` :key), which is deliberately **not** part of the projection — a Dart port is free to key its rows however it likes |

`reasoning` additionally: `text`, `streaming`.

`tool` (call + result + approval/ask all live on ONE block, keyed by `callId`):

| field | why |
|---|---|
| `callId`, `name` | the tool's identity; `""` name = a `tool_result` for a call the fold never saw |
| `status` | `running` / `done` / `error` / `interrupted` |
| `args` | the call's raw `arguments` (null when none) |
| `content` | the result text |
| `structured` | the wire's `tool_result.data.structured` (the fold keeps only a pretty-printed copy; the projection stores the wire JSON) |
| `isAsk` | `name === "hfy.ask_user"` |
| `questions` | normalized questions (`{id,text,type,required,placeholder,options}`) — the ask's argument set, possibly re-taken from `approval.requested.data.questions` |
| `answers` | the validated answers from `approval.decided.data.answers` (or the ask result fallback) |
| `askState` | only for question sets: `pending` / `other` / `answered` / `skipped` / `timeout` / `stopped` / `asking` |
| `decision` | `allowed` / `denied` from `approval.decided` |
| `declineReason` | the decision's `reason` (e.g. `timeout`) |
| `stopped` | the call settled with its turn's end (never awaiting a decision) |
| `showApproval` / `showDecided` | an open approval pause / it has settled |
| `showSummary` / `showDetails` / `hidden` | tool-call visibility (`P-FOLD-024`), projected for **every** tool block: summary row in summary mode (or a decided one under `hidden`), full details in `details` mode, and `hidden` mirrors the row's `is-hidden` (a no-content block or an unsurfaced question set) — exercised per mode by `tool-mode-{summary,hidden,details}.json` |
| `showPendingOwn` / `showPendingOther` | who must act on the open pause (the viewer -> sheet; others -> read-only note); plain approvals only |
| `card` | the tool's `hfy/ui` block verbatim (`{v,type, cards…}`) |
| `cardButtonsLive` | send/host buttons enabled: the turn is the viewer's own, currently the newest, and the viewer owns nothing active |

Dropped on purpose (presentation-only or environment-dependent): row/bubble
class names, DOM, Alpine internals and derived labels that quote the string
tables (`statusText`, `waitingText`, `askStateText`, `actorLabel`, tick
labels…), formatted day/time text (ISO `iso` and the day-separator/head booleans
`showDay`/`showHead` are kept; the label strings are not), avatar/hue classes,
fold-in-view geometry, token numbers/usage, and
`model.usage`/`summary` events — note the **UI fold ignores both** (no
projection possible for them; a Dart SDK that wants summary banners needs its
own decision). The sheet extends from `pendingOwn` deterministically, so only
its two settled outlets are projected (`sheetOpen`, `showActionPill`), never
the wizard's in-progress choices.

## `markdown.json`

`[{name, input, sha256, tree}]` — `input` hand-authored (one case per parser rule or
edge, including Arabic/RTL and emoji), `sha256` the real hash of that input
(only `-update-fixtures` rewrites it, so a hand-edited input fails loudly), and
`tree` generated by the real `hfyMdParse`. The tree is the parser's output
verbatim (`{t,c,v,href,level,lang…}` nodes, keys sorted only for storage); a
Dart SDK must build these trees — DOM building (`hfyMdBuild`) is out of scope
here.

## `strings.json`

`{"en": {…}, "ar": {…}}` — the exact tables generated from `HFY_STRINGS` in
`ui.js`. The test re-extracts them from the real file, so translation edits
fail the fixtures until regenerated.

## `tokens.json` — how it was measured

CSS tokens for light/dark and both densities plus accent-derivation vectors
(final computed values) for accents `#6366f1, #25d366, #e11d48, #0ea5e9,
#f59e0b`:

1. hfy was built from this repo (mock provider, fresh database `hfy_fixtures`
   in container `hfy-testdb`, 127.0.0.1:54330) and served `/embed` from
   `127.0.0.1:8630`.
2. `/embed` was opened as a **top-level page** in a fresh chrome-devtools tab;
   no grant was needed (the tokens land on `:root` as soon as the Alpine
   component mounts). The unrelated "hfy sim host" tab was left untouched.
3. theme/accent/density were switched with the documented `configure` bridge
   message (`window.hfy.receive({type:"configure", …})`).
4. Colors: a probe `<div>` was given `background-color: var(--X)` and read with
   `getComputedStyle` — the **final resolved color** (`color(srgb …)` /
   `rgb(...)`, `--hfy-on-accent` included, which is `hfyOnColor`'s AA fallback).
   Shadows: `box-shadow: var(--X)` probe. Sizes: raw
   `getComputedStyle(document.documentElement).getPropertyValue` (no `var()`
   inside them; identical across themes).

The full method is recorded inside `tokens.json` itself; its shape (sections
`method/themes/density/variables`, light+dark, 5 accents) is enforced by the
test, but its values can only be re-measured in a browser.
