# hfy_flutter parity matrix

Checklist for the native Flutter SDK `hfy_flutter` (`clients/flutter/hfy_flutter`): client + UI in one package.
It must reproduce the embedded web UI (`internal/httpapi/embed/{client.js,ui.js,ui.css,index.html}`) with **no functional or visual difference** except where the platform requires (Section 8).
Every later phase is built and reviewed against this file.

Conventions:
- **ID**: stable parity ID. **Source** cites the read-only embed sources (`client.js`, `ui.js`, `ui.css`, `index.html`, file:line). **Dart**: planned file under `clients/flutter/hfy_flutter/lib/src/`. **Test**: `unit` / `widget` / `golden`. **Status**: `todo` until implemented and reviewed.
- Rules: `fvm flutter` / `fvm dart` only; state management = Flutter built-ins (ChangeNotifier/ValueNotifier/ListenableBuilder/StreamBuilder); HTTP = dio.
- `UNVERIFIED` marks behavior the embed code hints at but that cannot be fully confirmed from these four files (server side or browser-runtime detail).

Row totals: 362 parity rows across §1–§9 (§8 allowed differences = 10 rows, §9 native-only = 12 rows, both counted within the 362).

UNVERIFIED ledger (all UNVERIFIED-flagged items in this matrix, so they are not read as invented):
1. P-CLIENT-033 — server-side handling of the browser-native `Last-Event-ID` header on EventSource auto-retry (client only proves the `?after` resume param).
2. P-MD-023 — ask answer rows are plain text everywhere in the sources; no markdown there is confirmed, treated as fact (not an UNVERIFIED feature).
3. Section 10a items describe server interactions (`live_after` semantics, `_awaitTurn`/`res.turn`) from the client contract; the server side of those payloads is not part of these four files.

### 10a. Bugs / inconsistencies found in the web UI (report, do not fix; Flutter replicates unless noted)

1. `sendDecisions` regex-matches the failing question's id inside the server error (`new RegExp('\\b' + q.id + '\\b')`, ui.js:1648) — special regex chars in a question id throw or mis-match; the crash lands the error unfocused. Dart should substitute an escape or a plain string search (escape).
2. Attach-menu/preview/doc pickers drop errors silently when ALL files are rejected while the preview is closed — the message shows only in the composer; combined with P-TL-003's silent loadOlder failure, several failure paths give no feedback (ui.js:1344-1345,1246).
3. Per-ask `waitOther` label uses the TURN's starter user label for anyone else's ask (ui.js:1105) — a second user interacting later shows the wrong "waiting for" name; only cosmetic under multi-viewer usage.
4. Timestamp foot requires `:has()` support for direction (ui.css:180-181) — browsers without `:has()` fall back to `inset-inline-end` regardless of content direction. Fine to replicate the modern behavior.
5. `flushPreview` allows Send when a caption exists and all uploads failed, then blocks at flush with the failure (ui.js:1409-1410) — two-step dead end (Send enabled → immediate error). Replicate the guard, skip the confusing enable.
6. In-item removal after the first failure never re-enables Send for a partial set (`flushPreview` only on upload settle - removing a failed item triggers syncPreview but the send disable is caption/items-based and re-evaluated correctly; removing ALL failed items while none ready sends the caption alone — by design but surprising).
7. `_awaitTurn` never clears when the server never echoes the turn's user message (ui.js:799-800) — Stop stays until an active-turn event lands. Same risk exists natively; document.
8. Confirm-question ids like `yes`/`no` collide with arg `hfyArgText`'s boolean wordmap only textually (no real bug), but `hfyAskComplete` accepts a confirm answer only as a real boolean for these. Fine.
9. Speculative asserts only — no other spectacle found from reading; the fold's idempotence (`settleCall` late-safety) is tested by the repo's own Go tests per commit history ("Stopped-ask settling is tested on every fold ordering").
